### 0.2 已知上限：不要再修的东西

**这一节是防止后来的人重复劳动。** 完整论证见
[SPFM时序精度上限.md](SPFM时序精度上限.md)。

SPFM 是给雅马哈 YM 系列设计的**写入数据流**协议：主机只能发 Path A
（`[slot,0x00,addr,data]`）、Path B（`[slot,0x80|n,data]`）、NOP（`0x80`），
`/WR`、`/CS`、`A0` 全由 STM32 固件在收到包之后自己产生。
**协议里没有引脚，没有 PHI2 概念，也没有回读通道。**

推论：

| 结论 | 理由 | 别做什么 |
|---|---|---|
| 主机唯一时间刻度是 6.667 µs（一个线字节的 NOP）或 `Sleep` 的 ~1 ms | UART 移位时钟 / Windows 调度 | 不要再试图"精确控制写间隔" |
| digi 的 `$D418` 能救 | 间隔 136 µs ≈ 20 个刻度，量化误差 5% | —— |
| 普通 PSID 的帧内抖动**无解** | 微秒级节奏 vs 6.667 µs 刻度，是采样定理问题 | **不要再加 pad 参数**，加了只会让普通曲子更糟 |
| Path A 两相间隔不可控不可测 | 由固件连发 | 想在两相间做文章只能改用 Path B 自己插 NOP |
| 写速率上限 37 500 条/s | 150 kB/s ÷ 4 字节 | 不要指望调参提上去 |
| 带宽不是瓶颈 | 最重曲目平均 17.9%、峰值帧 38% | 不要再做"降速/降采样"方案 |

另外两条**硬件层**的限制，写在这里免得被当成 bug 反复查：

- **`$D41B`（振荡器）/ `$D41C`（包络）读不回来。** SID 的数据总线只往一个方向走
  （374 占的是地址线，D0–D7 直接并到 SID），主机侧没有双向缓冲，也没有回读通道。
  所以靠读振荡器取随机的曲子会露馅。要解决得加一片 74xx245（手上的 74125 两片
  也够 8 位），属于改板，不是改软件。
- **`0xFE` 是全局复位，不能按槽复位。** 多 SID 场景下无法只复位一颗。

### 0.4 写时序是怎么解决的

**旧现象**：只有 `--repeat` ≥ 4 能让 SID 稳定发声；单次写入（repeat=1）是概率性的；
repeat 换来稳定的代价是**音高不跟随指令**（固定错误音高）。

**根因**：旧接线的 `/CS` 和 `R/W` 是两路不同源的信号——
`/CS = OR(CSn, LE)` 穿过两个 NOR 门（约 15–25 ns），`R/W` 直接裸接 `/WR`。
SID 在同一个 PHI2 沿同时采样这两个信号，边沿错开就可能采到"一个低一个高"，
这一笔写成非写非读的中间态。而且 `/CS` 在两相之间一直是低的，
SID 长期处于"半个写状态"，D 线上任何过渡都可能被当成数据。

**修法**：

1. `LE = NOR(A0, /WR)` 在地址相给 374 一个上升沿，锁住 `addr & 0x1F`；
2. `TRIG_n = ¬A0 ∨ /WR ∨ CSn` 把写条件编码成一个信号，**直连 SID 的 `/CS`（pin6）**；
3. SPFM 的 `/WR` **直连 SID 的 `R/W`（pin7）**。

旧接线的真问题只有一个：`/CS = OR(CSn, LE)` 在两相之间一直是低的，
SID 长期处于"半个写状态"，D 线上任何过渡都可能被当成数据。换成含 `¬A0` 的
`TRIG_n` 之后，地址相 `/CS` 恒高，问题消失。

**两次误判，都记在这里免得重走**：

| 误判 | 当时的结论 | 实测结果 |
|---|---|---|
| 按 reDIP-SID RTL 推断"写必须落在内部 18 周期轮转的第 1–6 周期" | 需要 ≥12 µs 窗口，设计了 PHI2 计数拉宽电路（164/595/174/273 四份） | ❌ 不需要。那 18 周期是软核**内部**写调度 |
| 拆掉 74HC74、`TRIG_n` **同时**接 `/CS` 和 `/R/W` 时声音失真 | 74HC74 是必需的整形器 | ❌ 真正原因是一个 74HCT32 门带两个 CMOS 负载拖慢边沿；两条线分开后 74HC74 可拆 |

**现在的认识**：6581 在这里就是**异步写器件**，`/CS` 与 `R/W` 同时为低就锁存，
和 YM2163 / YM7129 没有本质区别。datasheet 里 `TW` 的措辞是针对标准 C64 时序的
保守描述，不构成"必须等 PHI2"的约束。

**教训：FPGA 软核 RTL 可以解释芯片行为，但硬件时序只能以实测为准；
一次实测失败要先问"是不是还有别的变量没控制"，而不是直接归因到某个器件。**

详细推导与实测见 [写入时序调试记录.md](写入时序调试记录.md)，
接线见 [接线表_374_02_min.md](接线表_374_02_min.md)。

内置四首曲子：`twinkle`（小星星）、`ode`（欢乐颂）、`birthday`（生日快乐）、

```cmd

```

**钢琴感的关键：`sustain = 0`。** SID 的 sustain 是"按住键期间保持的音量"，
填 15 会让音符一直满音量直到下一个音（风琴长音），填 0 才会自然衰减到消失。
演奏循环还会在音符时值结束前一个 tick 主动降 gate，保证每个音都有干净的
0→1 重触发边沿。

**打击乐的"音高"是噪声时钟频率**，不是音高：

| 鼓 | 频率寄存器 | Decay | 听感 |
|---|---|---|---|
| 底鼓 | `0x0400` | 8（300 ms） | 低频隆隆 |
| 军鼓 | `0x0E00` | 7（240 ms） | 中频短促 |
| 踩镲 | `0x2400` | 5（168 ms） | 高频嘶声 |

衰减不能太短——早先版本用 `AD=0x00`（6 ms），听起来像数字干扰而不是鼓。

### 0.7 `.sid` 播放（已验证）

`.sid` 文件里是 6502 代码，不是音符。播放流程：

1. `src/sid_rsid.c` 用内嵌 6502（fake6502）+ VIC raster + CIA timer 跑一遍 init/play，
   把每次 `$D400–$D41F` 写入连同微秒时间戳记下来；
2. `src/sidplay.c` 在真硬件上按绝对 deadline 把这些写入推出去。

**仿真核心是从 STC32G 芯音乐工程原样搬过来的**（`usb_ctest/tools/sid_extract.c`），
只改了接口和机器状态复位，没有重写。原来那套 Python/py65 每首几分钟，现在是
**30 秒音乐 30 毫秒**。

三个关键决定，都是实测踩出来的：

| 问题 | 做法 | 效果 |
|---|---|---|
| 每个事件 `sleep(Δt)` 会累积误差 | 记一个起点，等 `起点+t` | 误差有界，不漂 |
| Windows `Sleep()` 精度 15.6 ms ≈ 一帧 | `timeBeginPeriod(1)` + 混合等待 | 10 秒 R-Type 最大滞后从 14 ms 降到 **2 ms** |
| 每次写都 flush 会把 50 次 USB 周转塞进一帧 | `sid_set_deferred_flush(true)`，每帧 flush 一次 | 字节顺序不变，传输次数少 50 倍 |

另有两个纯正确性修正：

- **init 期间的写入全部钉在 t=0**。早先按 CPU 周期算，R-Type 的 init 跑了 9 ms，
  结果 28 条初始化写入排在第一帧 play 之后，声音先响一下再被覆盖。
- **`play_addr = 0` 时先查 `$FFFE`，再查 `$0314`**。RSID 把 handler 装在硬件 IRQ 向量，
  PSID 装在 KERNAL 软 IRQ 向量，头里没有字段区分。`F1_Simulator`、`Flimbos_Quest`、
  `lazy` 三首只查 `$FFFE` 会得到 21 条写入就结束。

`sid/` 下 206 个文件（根 12、`games` 80、`rsid` 111 + `rsid/ganasis` 3）全部提取成功，
时间戳单调递增。
命令、参数、缓存见 [驱动说明.md §6](驱动说明.md) 和 README。

## 1. 硬件摘要

以 [接线表_374_02_min.md](接线表_374_02_min.md) 为准（已上机验证），这里只列信号级摘要：

```
SPFM 单槽                                         SID 6581
─────────                                         ────────
D0-D7 ─────────┬────────────────────────────────→ D0-D7 (pin 15-22)
               └──→ 74LS374 D0-D7
A0 ────────────┬──→ U2 pin2 (1A)                NOR(A0,/WR) → LE
               └──→ U2 pin5 (2A)                NOR(A0,A0)  → nA0
/WR ───────────┬──→ U2 pin3 (1B)
               ├──→ U3 pin2 (1B)
               └────────────────────────────────→ R/W  (pin 7)   ← 裸线直连
CSn ───────────────→ U3 pin5 (2B)
IC  ─────────────────────────────────────────────→ /RES (pin 5)
               U1 Q0-Q4 ────────────────────────→ A0-A4 (pin 9-13)
               U2 pin1 (1Y) ────────────────────→ U1 pin11 (CLK)
               U3 pin6 (2Y) ────────────────────→ /CS  (pin 6)
               1 MHz 有源晶振 ──────────────────→ PHI2 (pin 8)
```

译码只有三条：

```
LE      = NOR(A0, /WR)                  // U2 g1 → 374 的 CLK
nA0     = NOR(A0, A0) = ¬A0             // U2 g2 → 反相器
TRIG_n  = OR(nA0, /WR, CSn) = ¬A0 ∨ /WR ∨ CSn   // U3 g1+g2 → SID /CS
```

| `A0` | `/WR` | `CSn` | `LE` | `TRIG_n` | SID `R/W` | SID 侧 |
|---|---|---|---|---|---|---|
| x | 1 | x | 0 | 1 | 1 | 释放 |
| 0 | 0 | 0 | **1** | **1** | 0 | 374 抓地址；`/CS` 仍高，**SID 不响应** |
| **1** | **0** | **0** | 0 | **0** | **0** | **`/CS` 与 `R/W` 同时低 → 写入** |
| x | x | 1 | x | 1 | x | 本槽未选中 |

**必须保住的两条性质**（丢了就会退回排查期那些怪现象）：

1. **地址相 `/CS` 必须为高。** `TRIG_n` 里的 `¬A0` 保证这一点。丢了就在地址相
   误写，表现为"每次改频率都重启包络"的咔哒声。
2. **`TRIG_n` 只驱 `/CS` 一个负载。** 一个 74HCT32 门带两个 CMOS 负载会拖慢边沿，
   那正是早期"单次写入失真"的真正原因。`R/W` 单独接 `/WR`。

> 早期版本这里的写法是 `/CS_sid = OR(CSn, LE)`、`CSn → U2 pin5`，那是**旧接线**，
> 已被 §0.4 的排查否决。不要按旧的接。

## 2. 驱动层要做什么

主机侧只需要发字节流，一次寄存器写 4 字节：

```
[slot, 0x00, addr & 0x1F, data]
```

固件内部自动展开成两次 BusWrite：
1. `A0=0, D=addr&0x1F` → LE 上升沿，374 锁住 A0–A4
2. `A0=1, D=data` → /CS_sid 有效，SID 写入

**驱动不需要碰 A0–A3、/WR、CS、IC 中任何一个** —— 全由固件按路径 A 生成。

### 2.1 已实现的 API

完整说明见 [驱动说明.md](驱动说明.md)，头文件 `src/sid6581.h`。

```c
// 单寄存器写 / 批量
void sid_write(uint8_t slot, uint8_t reg, uint8_t data);
void sid_write_batch(uint8_t slot, const sid_reg_t *regs, size_t count);

// 初始化（清零全部寄存器 + 写音量 + 中性声部与滤波默认值）
void sid_init(uint8_t slot, uint8_t volume);

// 声部（voice = 0..2）
void sid_note_on(uint8_t slot, uint8_t voice, uint8_t midi_note,
                 uint8_t wave, uint8_t ad, uint8_t sr);
void sid_note_off(uint8_t slot, uint8_t voice);   // 走 release
void sid_note_kill(uint8_t slot, uint8_t voice);  // 立即静音
void sid_set_freq(uint8_t slot, uint8_t voice, uint16_t freq_reg);
void sid_set_pulse(uint8_t slot, uint8_t voice, uint16_t pw);
void sid_set_wave(uint8_t slot, uint8_t voice, uint8_t wave);

// 全局
void sid_set_volume(uint8_t slot, uint8_t volume);
void sid_set_mode(uint8_t slot, uint8_t mode);
void sid_set_filter(uint8_t slot, uint16_t cutoff, uint8_t resonance, uint8_t routing);

// 传输
bool sid_flush(void);
```

`sid_note_on` 内部顺序固定为 `freq_lo → freq_hi → AD → SR → ctl(wave|gate)`，
gate 必须最后写，否则包络会在频率未落定时启动。

### 2.2 缓冲策略

驱动只把字节追加到 64 KiB 缓冲，`sid_flush()` 才真正走 USB（4 KiB 一次 `FT_Write`）。
`sid_set_deferred_flush(true)` 让 `sid_write()` 只入缓冲，由播放器每帧 flush 一次——
一帧 50 个写如果各走一次 USB，2 ms 的 latency timer 会把 ~100 ms 周转塞进 20 ms 的帧。

`--pad` 模式下上限由 `spfm_set_flush_bytes()` 压到 2 KiB（13.6 ms 线上时间），
否则 64 KiB 缓冲意味着切曲要等 437 ms 的积压放完。`spfm_purge_tx()` 用于切曲时直接丢弃。

### 2.3 已知时序数据

| 项目 | 数值 | 备注 |
|---|---|---|
| 线速 | 1.5 Mbaud 8N1 → **150 000 B/s** | 10 bit/字节，6.667 µs/字节 |
| 路径 A 一次寄存器写 | 4 字节 = **26.67 µs** | 理论命令率 37 500 条/s |
| 路径 B 一次（旧 `2step`） | 6 字节 = 40 µs，另加两相间隔 | 命令率减半 |
| 三声部同时起音（5 次写/声部） | 15 次 ≈ 400 µs | 人耳听不出 |
| 每次 flush 的 USB 周转 | **2 ms**（latency timer） | 所以播放是每帧 flush 一次 |
| 一帧（PAL 19.96 ms）的写入预算 | 2694 字节 = **673 条命令** | 含 2 ms 周转 |
| 主机侧时间刻度 | 6.667 µs（NOP）或 ~1 ms（`Sleep`） | **这是硬上限**，见 §0.2 |
| 实测最重曲目带宽占用 | 平均 17.9%，峰值帧 38% | 4–5 倍余量，不需要降速 |

MIDI 场景完全够用。**但"精确节奏"不是带宽问题，是刻度问题**——
详见 §0.2 和 [SPFM时序精度上限.md](SPFM时序精度上限.md)，不要再往这个方向投入。

## 3. SID 寄存器速查

### 3.1 声部映射

| 功能 | 声部1 | 声部2 | 声部3 | 位宽 |
|---|---|---|---|---|
| 频率低 | 0x00 | 0x07 | 0x0E | 8 |
| 频率高 | 0x01 | 0x08 | 0x0F | 8 |
| PWM 低 | 0x02 | 0x09 | 0x10 | 8 |
| PWM 高 | 0x03 | 0x0A | 0x11 | 4（低 4 位） |
| 控制 | 0x04 | 0x0B | 0x12 | 8 |
| Attack/Decay | 0x05 | 0x0C | 0x13 | 4+4 |
| Sustain/Release | 0x06 | 0x0D | 0x14 | 4+4 |

### 3.2 全局寄存器

| 地址 | 功能 |
|---|---|
| 0x15 | 滤波器截止 低 3 位（bit2–0） |
| 0x16 | 滤波器截止 高 8 位 |
| 0x17 | 谐振（bit7–4）+ 滤波通道使能（bit3=ext, bit2=v3, bit1=v2, bit0=v1） |
| 0x18 | bit7=断开声部3输出、bit6=高通、bit5=带通、bit4=低通、bit3–0=音量 |

复位后 0x18 = 0，**必须写非零音量才出声**。

注意原文档把 0x18 的 bit4–7 写成了"关闭各波形"，那是错的。0x18 的高 4 位是
滤波器模式选择和声部 3 静音，不是波形开关（波形只在各声部的 0x04/0x0B/0x12 里选）。
`0x18 = 0x1F` 的含义是"低通滤波打开 + 音量 15"，`0x18 = 0x0F` 是"无滤波 + 音量 15"。

### 3.3 控制寄存器位

| bit | 功能 |
|---|---|
| 0 | **gate**（1=起音，0=释放） |
| 1 | sync |
| 2 | ring mod |
| 3 | test |
| 4 | triangle |
| 5 | sawtooth |
| 6 | pulse |
| 7 | noise |

同一时刻只能选一种波形（多位同时置会得到奇怪的混合波形）。

### 3.4 频率换算

```
freq_reg = f_out × 16777216 / PHI2
```

1MHz 下：

| 音符 | MIDI | freq_reg |
|---|---|---|
| A2 | 45 | 1845 |
| C4 | 60 | 4389 |
| A4 | 69 | 7382 |
| C6 | 84 | 17557 |
| C7 | 96 | 35115 |

参考 `E:\working\zcode-projects\arduino_sid\midi.c` 的 `freq[]` 数组（1MHz 标定，note 12–108 共 97 项）。

### 3.5 PWM

12 位，范围 0–4095。`2048` = 50% 方波。写顺序：先低 8 位（+2），再高 4 位（+3，仅低 4 位有效）。

### 3.6 ADSR

每个半字节 0–15，映射到表格化的 ms 值（Attack 2ms–8s，Decay/Release 6ms–24s）。注意 **0 = 最快，不是关闭**。

## 4. 初始化序列

```
1. 清零全部寄存器（0x00-0x18 写 0）  — 避免上电不定态
2. 0x18 = 0x0F                         — 音量 15（必须）
3. 各声部 ADSR（0x05/0x06、0x0C/0x0D、0x13/0x14）
4. 各声部 PWM（0x02/0x03 等）
5. 滤波器（可选）：0x15、0x16、0x17
6. 各声部控制寄存器写波形（gate=0）
```

因为 SPFM 只有全局复位 `0xFE`（不能按槽控 IC），上电后靠软件清零最可靠。

## 5. 风险与待验证

| 项 | 说明 | 优先级 |
|---|---|---|
| **USB 抖动 / PSID 帧内时序** | **协议上限，不可修复**。见 §0.2 与 [SPFM时序精度上限.md](SPFM时序精度上限.md)。不要当 bug 查 | 已确认为上限 |
| **374 上电不定态** | Q 输出随机，需软件先清零 | 高（`sid_clear_all_regs` 已覆盖） |
| **`TRIG_n` 门控是否生效** | 数据相 `U3 pin6` 应为低、地址相应为高。接错会出现每次起音咔哒 | 高（首次调试必查） |
| **`TRIG_n` 负载** | 一个 32 门只能带 `/CS` 一个 CMOS 输入；同时带 `R/W` 会拖慢边沿 | 高（勿回退） |
| **12 V 供电** | 6581 缺 12 V 完全无声，且不易察觉 | 高 |
| **PHI2 频率** | 现在按 1.000 MHz 标定；换 0.985 MHz 晶振要改 `SID_PHI2_HZ_DEFAULT` 并重生频率表 | 中 |
| **`$D41B/$D41C` 读不回** | 硬件没有双向缓冲，影子值不是真读 | 中（见 §0.2） |
| **多 SID 槽** | `0xFE` 是全局复位，无法单槽复位；`slot` 参数已预留 | 低 |

### 5.1 首次上电必做测试

按 [接线表_374_02_min.md](接线表_374_02_min.md) 的编号（U1=374，U2=02，U3=32）：

1. 量 Y1 输出是否 1 MHz（SID pin 8）
2. 量 SID pin 25 = 5 V、pin 28 = 12 V
3. 写 `[3, 0x00, 0x18, 0x0F]`，万用表量 pin 27 是否有直流偏移（≈ 1/15 × 12 V × 音量）
4. 写 `[3, 0x00, 0x04, 0x11]`（三角波 + gate），示波器看 pin 27 是否出波形
5. 若无声，按顺序量：
   - 数据相（`A0=1` 且 `/WR` 低）时 **`U3 pin6`** 是否为低 → 否则写条件没译码出来
   - 地址相（`A0=0`）时 `U3 pin6` 是否保持为高 → 若不是，`¬A0` 那一路断了，
     会在地址相误写（听感是每次改频率都咔哒）
   - `U1` Q0–Q4 到 SID pin 9–13 是否连通
   - `U2 pin1` 在地址相是否有一个上升沿（374 抓地址的时刻）
