# 直驱还是锁存：RP2350A 接 SID 6581 的电路与驱动审计

> 2026-11-26。对照 `refs/USBSID-Pico-master`（"USBSID"）回答三个问题：
>
> 1. 是否真的需要独立的片选线？
> 2. 是否真的需要改电路？
> 3. 能否取消锁存（374），把地址线直接从 GPIO 送出去？
>
> 结论先说：**当前方案没有时序硬伤，但有一处真实的架构冗余——`/CS` 在固件里
> 是常量。锁存器是 SPFM 时代留下的包袱，可以在下一次打板时整组删掉（3 颗 IC），
> 但今天不改也能正常工作。**

---

## 1. 先看清现状电路到底在做什么

### 1.1 三条逻辑

```
LE      = NOR(A0, /WR)              // U2 g1 → 374 的 CLK
nA0     = NOR(A0, A0) = ¬A0         // U2 g2 → 反相器
TRIG_n  = OR(nA0, /WR, CSn)         // U3 → SID pin6 (/CS)
        = ¬A0 ∨ /WR ∨ CSn
```

固件侧（`rp2350/src/main.c`）：

| 位置 | 内容 |
|---|---|
| `main.c:118` | `cs_select(slot)` → `cs_pack(slot) = 0x03 & ~(1<<slot)` |
| `main.c:377` | `write_reg_sid()` 第一句就是 `cs_select(0)` |
| `main.c:100` | `CS_IDLE 0x03` 只在 `pio_cs_init()` 里用一次 |

`cs_pack(0)` = `0b10`，即 **CS0# 拉低、CS1# 保持高**。之后再也没有任何地方把它拉回
`CS_IDLE`。

### 1.2 由此得到一个不太舒服的事实

**CS0# 从上电第一次写之后就是常量 0，永远不翻转。**

代进 `TRIG_n`：

```
CSn = 0  →  TRIG_n = ¬A0 ∨ /WR
```

CS 项彻底消失。所以现在这颗 GPIO12、pio1 的一个状态机、74LVC245 的一路通道、
74HCT32 的一个输入，全都在服务一个恒为 0 的信号。

> 这不影响出声——`TRIG_n` 只要有 `¬A0` 和 `/WR` 就够区分地址相和数据相。
> 反过来，如果哪天真把 CS 拉高，反而会完全写不进去（`TRIG_n` 恒 1）。

### 1.3 一次写在总线上长什么样

`spfm_bus.pio:128-135`，每写一次推 7 组以上的字：

| 字 | A0 | D0–D7 | /WR | 作用 |
|---|---|---|---|---|
| 1 | 0 | `addr & 0x1F` | 1 | 地址建立 |
| 2 | 0 | `addr & 0x1F` | **0** | `LE` 上升，374 抓地址 |
| 3 | 0 | `addr & 0x1F` | 1 | `LE` 落下，地址已锁存 |
| 4 | 1 | `data` | 1 | 数据建立 |
| 5..5+N-1 | 1 | `data` | **0** | `TRIG_n` 与 R/W 同时低 = 写窗口 |
| 5+N | 1 | `data` | 1 | 释放 |
| 忙 | — | 0xFF | 1 | 总线空闲 |

每个字由 PIO 自己等 PHI2（`spfm_bus.pio:61-63`，`wait 0 → out pins → wait 1`），
所以每个字正好一个 PHI2 周期（PAL 1.015 µs）。N = `SID_HOLD` = 12（`main.c:352`）。

**一次写 = 3 + 12 + 2 = 17 个周期 ≈ 17.3 µs**，实测 18.9 µs（含 `pull`/wrap 开销）。

地址相为什么要 3 个字：因为数据总线是分时复用的，`LE` 需要一个上升沿再一个下降沿，
再加上前面一次地址建立。这三步**只是为了把地址从数据总线里拆出来**。

## 2. 参考项目 USBSID 是怎么做的

### 2.1 没有任何锁存芯片

`src/gpio_defs.h`：

```c
#define D0 0
...
#define D7 7
#define A0 8
#define A1 9
#define A2 10
#define A3 11
#define A4 12
#define A5 13
#define RW   19
#define CS1  20
#define CS2  21
#define PHI1 22
```

`src/pio.c`：数据+地址是**一个 14 位的连续输出组**，控制线是**另一个 3 位的组**。

```c
sm_config_set_out_pins(&c_data,    D0, A5 + 1);   /* 0..13 共 14 根 */
sm_config_set_out_pins(&c_control, RW, 3);        /* 19..21 共 3 根 */
```

`src/bus.c:98`，地址和数据在**同一个字**里一起送出去：

```c
data_word = ((address & 0x1F) << 8) | data;   /* 上 8 位 A0-A5，下 8 位 D0-D7 */
```

`src/pio/bus_control.pio` 与 `data_bus.pio` 用 IRQ 让两个状态机错开一个节拍：
数据/地址在 PHI1 **低**相建立，控制字在**下一个**低相才落下——这一个周期就是
地址建立时间。写窗口的长度由 `delay_timer.pio` 数 PHI1 周期决定，不靠主机猜。

### 2.2 所以两种方案的差别只有一个

| | USBSID | 本项目 |
|---|---|---|
| 地址线来源 | 6 根专用 GPIO | 借用 D0–D4，靠 374 重建 |
| 片选 | 和 RW 同在控制字里，每写都跟着动 | 常量 0 |
| 每写字数 | 建立 1 + 窗口 N + 释放 1 | 3 + N + 2 |
| 元件 | 0 片逻辑 | 374 + 02 + 32 = 3 片 |
| 3.3 V 电平 | 直连（6581 VIH = 2.0 V） | 经 74LVC245 |

**锁存器存在的唯一理由是"地址线不够"。** SPFM 年代只有 A0 一根地址/相位位，
必须靠两相总线把 5 位地址挤进数据总线。RP2350A 有 12 根空闲 GPIO，这个前提
已经不存在了。

## 3. 当前方案的三个架构问题

按严重程度排序。**都不是时序硬伤**，都是"能工作但没必要"。

### 3.1 锁存器把地址从数据总线里拆出来 —— 纯遗留

代价：

- 3 颗 IC、6 根额外走线、每写多 3 个 PHI2 周期（18.9 µs vs 约 15.5 µs，省 16% 总线时间）。
- 一个上电隐患：374 上电后 Q 是不定态，必须先显式写一次把地址归零
  （`接线表_374_02_min.md` §8 ⑧ 记录过）。
- `LE` 与 `/CS` 不同源，多片 SID 时 `LE` 不看 CS，会往别的芯片里锁垃圾地址
  （见 3.2）。

### 3.2 多片 SID 时锁存器会串片

`LE = NOR(A0, /WR)` 与 CS 无关。写 2 号芯片时，1 号芯片的 374 也在同一个 `LE`
上升沿抓走了 2 号芯片的地址。结果是每片 SID 的地址寄存器都被别人的写污染。

现在没暴露，是因为上游直接拒绝多芯片（`src/sid_lsfp.cpp:257` 与 `:411`，
`sidChips() > 1` 直接报错）。但曲库里确实有 2SID 曲子
（`sid/rsid/Anthrox_2SID.sid`、`sid/rsid/Hokuto_Stereo_2SID.sid`）。
**直驱之后这个限制自然消失**，因为每片都有自己的 A0–A4 和真片选。

### 3.3 片选是常量，`/RD` 从没被拉低过

- CS：如上，恒 0。占 1 根 GPIO、1 个 PIO 状态机、1 路 245、1 个 32 输入。
- `/RD`：`pack_bus()` 的 `rd_n` 参数在全部调用点都是 `true`，GPIO9 与 245 的一路
  通道从未使用。

这两条属于"账面浪费"，不影响声音。

## 4. 现在有没有时序硬伤？没有

用四个数把这件事钉死（工具在 `rp2350/tools/`，`scripts/build_probes.sh` 编译）：

| 度量 | 实测 | 结论 |
|---|---|---|
| 主机推帧能力（`hidbench`） | 6846 帧/s = **102 687 事件/s** | 余量巨大 |
| 板子连续写能力（`wbench`，hold=12） | 18.9 µs/写 = **52 907 写/s** | 余量巨大 |
| 全曲库最重 20 ms 窗口 | `turboutrun_s02` 207 次 = **19.6% 容量** | 0 首超限 |
| 曲库中位峰值 | 28 次/20 ms = **2.6% 容量** | 完全空闲 |

唯一能观测到的真实影响是**写入下限造成的轻微时长拉伸**：把 18.9 µs 当作最小
间隔后，全曲库 697 首里中位数只多 0.51% 时长，最坏的 `stsid.sidvgm` 多 4.5%
（它的相邻对里有 49.5% 是 `dt=0`，即连奏）。

也就是说：**18.9 µs 这个下限只在最密的连奏段让音乐慢了零点几个百分点。**
它不是一个 bug，是"每个写要占 17 个周期"的必然结果。

> 顺带排除一个常见怀疑：`dt=0` 的连发不是录制错误。完整曲库里低于 18.9 µs 的
> 间隔有 2534 万个，其中 **75.4% 是"同一寄存器写同一个值"**——C64 代码在轮询里
> 反复写相同的值，本来就没有时间含义。真正带信息的高速段只占四分之一。

## 5. 三个可选方案

### 方案 A —— 什么都不动（推荐，除非要打板）

现在能出声，digi 正常，吞吐余量 5 倍以上。上面三个问题都是"效率"而非"功能"。
**不改电路就不会引入回归**，而 digi 的 `/CS` 窗口是上一轮花了很大力气才调对的
（`SID_HOLD=12`，`spfm_bus.pio` 注释里有完整复盘）。

### 方案 B —— 一行硬件改动：CS 焊死为 0

如果确定永远只用一片 SID：

- 把 74HCT32 的 CS 输入（U5 pin5）直接接 GND；
- 固件里删掉 `cs_select(0)` 调用和整个 `pio_cs`（省一根 GPIO + 一个状态机）。

风险：**从此不能加第二片 SID**，因为 `TRIG_n` 会变成 `¬A0 ∨ /WR`，两片同时被选中。
而且 `LE` 的串片问题依旧。

这一改动的收益很小（只省 GPIO），**除非你正好要为别的东西腾引脚，否则不建议**。

### 方案 C —— 打板时取消锁存，照抄 USBSID（真正的简化）

删掉 374 + 02 + 32 三颗 IC，地址直接进 GPIO。引脚表可以**逐根对上 USBSID**：

| 信号 | 新 GPIO | 说明 |
|---|---|---|
| D0–D7 | 0–7 | 不变；仍建议经 74LVC245（见 §6） |
| A0–A5 | 8–13 | `out pins, 14` 与数据同一个字，A5 留给第二片 |
| PHI2 | 14 | 不变（PIO 输出） |
| DIR | 15 | 74LVC245 pin1（只护数据线） |
| WS2812 | 16 | 板载，不可动 |
| RW（即 /WR） | 19 | 控制组起点 |
| CS0# / CS1# | 20 / 21 | `out pins, 3`，每片一根，真片选 |
| IC# | 22 | 从 21 挪开 |
| LED | 25 | 板载，不可动 |

相对现在的引脚表，净空出 GPIO11（原 DIR，DIR 挪到 15）；17、18、26–28 本来就空。
原 GPIO8/9/10 的 `/WR`、`/RD`、`A0` 直接变成 `A0`、`A1`、`A2`——不需要挪线，
只是含义变了。GPIO22 现在是空的（已实测，见
[板载资源_RP2350A.md](板载资源_RP2350A.md)），正好给 `IC#`。

PIO 程序从"7+ 个字"变成 3 段：

```
字 1        A0-A5 + D0-D7 建立，CS=1 RW=1
字 2..N+1   同上，CS=0 RW=0        ← 写窗口，N = SID_HOLD
字 N+2      释放
```

时序上唯一要保住的一条（USBSID 也是这么做的）：**地址/数据必须先建立，CS 晚一个
PHI2 周期才落下**。这正好是 6581 datasheet 的地址建立时间要求，而且只花一个周期。

收益：

| 项 | 现方案 | 直驱 |
|---|---|---|
| 逻辑 IC | 3 片 | **0 片** |
| 每写周期数 | 17（实测 18.9 µs） | 14（约 15.5 µs，hold=12） |
| 片选 | 常量 | **每片独立** |
| 多片 SID | 不支持（上游拒绝） | 支持，且无串片 |
| 上电 374 不定态 | 需显式清零 | 不存在 |
| 时长拉伸（中位/最坏） | 0.51% / 4.5% | 0.42% / 3.7% |

代价：要重画一次板、改 `spfm_bus.pio` 与引脚表、重新验证 digi 与 `SID_HOLD`。

## 6. 74LVC245 要不要一起去掉？

USBSID 是**直连的**，没有电平转换。3.3 V 高于 6581 的 `VIH = 2.0 V`，地址、
`/CS`、`R/W` 这些纯输入脚直连完全合规。

但数据总线不一样：**SID 在读周期会把 5 V 打回数据线**（`$D419/$D41A/$D41B/$D41C`
这些寄存器）。RP2350 的 GPIO **不耐 5 V**。

本项目自己不读（读的副作用在录制阶段由 libsidplayfp 算完了，`.sidvgm` 里只有写），
而且 `/CS` 为高时 SID 的数据口是高阻，所以直连在逻辑上安全。
**但它把"接线错一次就烧 MCU"的容错度降为零。**

建议：

- **数据线保留 74LVC245**（1 颗，1 根 DIR），只当保护和驱动；
- **地址线与控制线不需要 245**，直连即可——省掉第二颗 245 的 6 路通道。

## 7. 结论

1. **独立片选线：现在是假的。** 固件把它焊死在低电平，它没有在做任何选择工作。
   要么让它变成真的（方案 C，每片一根），要么干脆承认不需要（方案 B，接 GND）。
   "片选可单独控制时序"这句话在当前固件里不成立。
2. **要不要改电路：不必为时序改。** 没有时序硬伤：板子每秒能写 5.3 万次，
   最重的曲子只用掉 19.6% 容量，写入下限只让最密的连奏慢零点几个百分点。
3. **锁存器：可以取消，而且取消了更好。** 它是"地址线只有一根"年代的产物。
   RP2350A 有 12 根空闲 GPIO，照 USBSID 的 14 位数据+地址字直驱，可以省掉 3 颗
   IC、把每写从 17 个周期降到 14 个（省 3 µs），并顺带让多片 SID 变成可能。
   **但这是打板时的事，不是现在的事。**

优先级：**不动的收益 > 方案 C 的收益 > 方案 B 的收益**。
真要动手，就攒到下一次打板一次做完，别单独去动 `/CS` 那根线。
