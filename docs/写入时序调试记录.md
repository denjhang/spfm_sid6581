# 写入时序调试记录 — SID 6581 在 SPFM 上的实际表现

> 记录日期：2026-11-19。硬件：74LS374 + 74HCT02，SID 6581 接 RE-SPFM **slot 3**，
> PHI2 = 1.000 MHz（模块自带晶振），`+12 V` 正常。
>
> **本文只记录实测结果和由此得出的推断，不含未验证的结论。**

## 0. 一句话结论

**目前只有"重复写（repeat）"能让 SID 稳定发出延音**。单次写入（repeat=1）是概率性的：
每次运行能成功的时序参数都不一样。推测这是 SPFM 与 SID 在时序层面先天不匹配导致的，
理由见 §4。

## 1. 排查过程中修掉的问题（已确认）

| 问题 | 表现 | 修复后 |
|---|---|---|
| SID pin 5 `/RES`（SPFM `IC`）接错 | 全程只有总线串音，无任何音调 | 接对后立刻出现真实三角波 |
| `0x18` 文档描述错误 | 原文档说 bit4–7 是"关闭各波形"，实际是滤波器模式 + 声部 3 静音 | 已改文档 |
| `freq[]` 参考表两处错误 | note 23 抄成 C#1；note 99–107 整体低一个半音 | 驱动改用公式生成的表 |

修完这三项后，**第一次** `xtalk` step 4 出现了一声准确的 A4 三角波（约 1 秒），
之后再也无法稳定复现。

## 2. 实测数据

### 2.1 `retry`：只改重试次数（两步写入 + 每笔独立 USB 传输）

| repeat | 结果 |
|---|---|
| 1 | 偶尔音高正确，多数时候是错的固定音高 |
| 2、3 | 不稳定 |
| **4 – 16** | **稳定延音** |
| 24 及以上 | 声音反而变短 |

### 2.2 `prelude`：只改起音前的残留状态（repeat=8，两步写入）

| # | 前置 | 结果 |
|---|---|---|
| 1 | reset → init → note | ✅ 长音 |
| 2 | init → note（不复位） | ❌ 无 |
| 3 | reset → 刷 2000 次总线 → init → note | ✅ 长音 |
| 4 | reset → init → 刷 2000 次总线 → note | ❌ 无 |
| 5 | init ×4 → note | ❌ 无 |
| 6 | 完全不 init → note | ✅ 长音 |
| 7 | reset → 停 3 秒 → init → note | ✅ 长音 |

结论：**`0xFE` 全局复位对 SID 是必要的**（对比 1 vs 2）；init **之后**再乱刷总线
会把状态弄坏（对比 3 vs 4）。

### 2.3 `xtalk`：13 种时序组合

| 参数 | 结果 |
|---|---|
| burst（Path A，固件内部连发两相） | ❌ 无延音 |
| tight（两相零间隔） | ❌ |
| nop 1/2/3/4/6/8/16/32（硬件 NOP） | ❌ 全部无延音 |
| soft 90µs / soft 500µs（主机 sleep） | ❌ |
| path-a + soft 90µs | ❌ |

**所有单次写入的时序组合都失败。**

### 2.4 `norep`：一条写一次 USB 传输，gap 扫 0–8，repeat=1

| 结论 |
|---|
| gap 0 / 1 / 5 / 6 都曾出现过声音 |
| **每次运行能成功的 gap 都不一样**，没有固定值 |

这是最关键的一条：它说明单次写入的成败**不是**由 gap 决定的，而是由 USB 传输
起始时刻与 PHI2 的相对相位决定的，而后者是随机的。

### 2.5 已知可用的组合

```powershell
# 稳定，但初始化慢、首音有约 0.5 秒延迟
.\sidtest.exe tone --note 60 --secs 3 --write-mode two-phase --delay 0 --repeat 8

# 稳定且立刻发声（推荐）
.\sidtest.exe tone --note 72 --secs 3 --write-mode two-phase-nop --gap 3 --repeat 12
```

### 2.6 音高问题

| 配置 | 音高 |
|---|---|
| repeat=1 | 有概率跟随指令 |
| repeat ≥ 4 | **固定错误音高**，与指令无关 |

即 repeat 能换来"稳定发声"，但代价是"音高不再跟随"。这两者目前无法同时满足。

## 3. 字节时序的算术

这是整份记录里最有价值的部分。

| 项目 | 数值 |
|---|---|
| 波特率 | 1.5 Mbps |
| 每字节（8N1，10 bit） | **6.6667 µs** |
| Path B 一条命令（3 字节） | **20.000 µs** |
| 两相写入（6 字节） | **40.000 µs** |
| 两相 + gap 3（9 字节） | **60.000 µs** |
| Path A 一条命令（4 字节） | 26.667 µs |
| PHI2 周期 | **1.000 µs** |

**3、6、9 字节分别正好是 PHI2 周期的 20、40、60 倍。**

也就是：**用这几个"整齐"的命令长度时，每一次写入都落在 PHI2 的同一个相位上。**
N 次重试不是 N 次独立机会，而是**同一次机会重复 N 遍**——要么全中，要么全丢。
加 gap 3 同样保持整数倍（9 字节 = 60 周期），没有打破这个锁死关系。

只有 gap 不是 3 的倍数时相位才会移动（每多 1 个 tick ≈ 6.67 µs ≈ 0.67 个周期），
但移动量本身又被 USB 传输起点的抖动所污染，所以 `norep` 里表现为随机。

## 4. 为什么怀疑 SPFM 与 SID 先天不兼容

### 4.1 SID 的写入协议要求什么

6581 的寄存器写入条件是**同时满足**：

1. `/CS` 低；
2. `R/W` 低；
3. **PHI2 出现上升沿**（SID 在 PHI2 上升沿采样总线）。

也就是说，写脉冲必须**跨过**一个 PHI2 上升沿。

### 4.2 SPFM 能提供什么

SPFM 的总线时序与 PHI2 **没有任何关系**：

- `/WR` 脉冲宽度由 STM32 固件决定（数百纳秒量级）；
- 而 PHI2 由模块上的晶振独立产生，1 MHz。

一个 ~200 ns 的 `/WR` 低电平窗口，落在 1 µs 周期内的某个位置。若窗口不跨越
PHI2 上升沿，SID 就**不会锁存**，而且**没有任何反馈**——写"成功"还是"丢失"，
主机完全看不出来。

粗略估算命中率：200 ns / 1000 ns ≈ **20%**。这与 `norep` 观察到的"偶发成功"吻合。

### 4.3 与 YM7129 / YM2163 的对比

| 芯片 | 主机接口是否需要时钟参与 | SPFM 能否满足 |
|---|---|---|
| YM2163 | 不需要，`/CS` + `/WR` 下降沿即写入 | 能 |
| YM7129 | 不需要（只需写间隔 ≥ 89.2 µs） | 能 |
| **SID 6581** | **需要：PHI2 参与采样，且写入必须落在内部 18 周期轮转的第 1–6 周期** | **不能保证** |

这正是两个参考项目都工作的原因：它们的写入是**异步**的，SPFM 的异步总线完全够用。
SID 是三者中唯一有**同步写要求**的芯片。

### 4.4 FPGA 软核源码的直接证据

这不是推测，是从开源 SID FPGA 实现的 RTL 里读出来的。

**证据 1：reDIP-SID 的写条件（`gateware/sid_control.sv`）**

```systemverilog
// Register read / write.
r =  bus_i.phi2 &  bus_i.r_w_n && maddr >= 0 && maddr <= 3;
w = ~bus_i.phi2 & ~bus_i.r_w_n && voice_cycle >= 1 && voice_cycle <= 6;
```

写必须同时满足三项：`PHI2 为低`、`R/W 为低`、**当前处于 18 周期轮转的第 1–6 周期**。
这个 18 周期轮转完全由 PHI2 驱动，SID 内部没有别的时钟源。

**证据 2：reDIP-SID 的总线锁存方式（`gateware/sid_io.sv`）**

```systemverilog
phi1_io = ~phi2_io;   // PHI2 反相作为 D 锁存使能
// addr / data / cs / r_w_n 四个信号全部用 phi1 作为 LATCH_INPUT_VALUE
.LATCH_INPUT_VALUE (phi1_io)
```

即：PHI2 低电平期间锁存器透明，PHI2 一升变就关闭保持。**总线是在 PHI2 上升沿被采样的。**
源码注释也写明了这一点："so that the signal can be used to latch other signals"。

**证据 3：MOS 6581 数据手册**

```
φ2 (phi2) — Input for system oscillator, receives data only when high
TW  Write Pulse Width  min 350 ns
    "TW is measured from the latest occurring of φ2, CS, R/W"
```

`TW` 的定义本身就是三者中最晚发生的那一个开始算，说明三者在 SID 眼里是并列的采样条件，
缺一不可。而且最小值 **350 ns** 已经大于我们一条 BusWrite 的 `/WR` 宽度量级。

**反证：雅马哈类的异步接口**

OPL2 FPGA 核的 `host_if.sv`：

```systemverilog
always_comb wr_p1 = !cs_p1_n && !wr_p1_n;   // 纯电平与，无时钟
afifo (.i_wr(wr_p1 && !wr_p2), .i_wr_data({address_p1, din_p1}), ...);
```

只有 `/CS` 和 `/WR` 的下降沿，推进 FIFO 就完事。YM2413/OPLL 根本没有 PHI2 引脚，
时钟只用于内部合成，不参与总线采样。icesid 更直接：SPI 收到数据后 `busWE <= 1`，
写使能就是一个普通电平。

**结论：SID 的总线是同步的，雅马哈的总线是异步的。这是两者唯一的、也是致命的差别。**

### 4.5 所以"repeat 能出声"是怎么来的

repeat 把一个固定相位的写机会重复多次，靠的是两点偶然性：

1. 每条命令各占一次 USB 传输时，FT232R 的调度抖动（0–125 µs）会把相位打散，
   N 次重试就变成 N 次独立机会。命中概率约 1 − 0.8^N（N=12 时约 93%）。
2. 一旦某次命中，寄存器被写入；但因为相位关系是**确定**的，每次运行里
   "哪些寄存器命中、哪些丢失"是同一个子集，于是结果表现为**固定但错误的音高**。

因此 repeat 不是解决方案，而是**用冗余掩盖丢写**。它牺牲了音高正确性。

## 5. 硬件解决方案：把写窗口拉宽到覆盖多个 PHI2 周期

### 5.1 先明确哪些线是"太短"的

按现有接线（[接线表_374_02.md](接线表_374_02.md)）：

```
LE      = NOR(A0, /WR)
/CS_sid = OR(CSn, LE)
R/W     = /WR        （直接接 SID pin 7）
```

数据相时 `A0=1`，所以 `LE = NOR(1, x) = 0`，于是：

```
/CS_sid = OR(CSn, 0) = CSn
```

**`/CS` 在整个数据相期间都是有效的，长度是微秒级，不缺。**
真正过短的是 **`R/W`**——它直接来自固件的 `/WR` 脉冲，只有数百纳秒。

所以"换 373 / 574 / 374"没有任何帮助：它们只影响地址锁存那一侧，
对 `R/W` 的宽度毫无影响。三类锁存器的差别（373 电平透明、374/574 边沿触发）
与"写脉冲能否跨过 PHI2 上升沿"这个问题完全无关。

### 5.2 解决方案：用 PHI2 计数拉宽写窗口

**接线详见四份完整接线表之一（网络标签一致，任选其一）：**
[HC164](接线表_374_02_74_164.md) / [74273](接线表_374_02_74_273.md) /
[HC595](接线表_374_02_74_595.md) / [74174](接线表_374_02_74_174.md)。
选型对比见 [接线表_374_02_74.md](接线表_374_02_74.md)。这里只写原理。

早期版本本节推荐过 74HC123 RC 单稳态（`tw ≈ 5.6 µs`），有两个问题：
一是手上没有 123；二是 RC 宽度随温度/器件漂移，还得拿示波器逐块标定。
改成**用 PHI2 自己当节拍器**：一颗 74HC74 锁存出窗口，移位寄存器数 PHI2，
数到第 N 格就把窗口关掉。

```
SPFM A0 ──┐
SPFM /WR ─┴─→ TRIG_n = ¬A0 ∨ /WR ∨ CSn ──→ 74HC74 1/PRE（异步置位）
                                              │
                                              ├─ Q  → 74HC164 串行输入，CP = PHI2
                                              │
                                              └─ /Q = Wn ──→ SID pin6 (/CS)
                                                          └→ SID pin7 (R/W)

74HC164 第 N 格 tap ──→ 反相 ──→ 74HC74 1/CLR（异步清零）
```

窗口长度 = **N 个 PHI2 周期**，1 MHz 下就是 N µs，不做 RC、不漂移；
PHI2 换成 0.985 MHz（8580 的晶振）也自动跟着变，不用重调。

**窗口取 14 µs（tap = 第 14 级）**，不是早期版本的 3 µs。原因是 18 周期轮转里
只有第 1–6 周期可写，若要"无论起点在哪都必定命中"，需要 `W + 6 ≥ 18`，即 `W ≥ 12 µs`。
3 µs 只能把命中率从 20% 提到约 50%，仍然是概率事件。

器件数量：**74HC74（1 颗，用 1 个触发器）+ 74HC164（2 颗级联到 16 级）**。
只装 1 颗 HC164 时 tap 取第 8 级，窗口 7–8 µs，命中率约 75%，配合 `--repeat 2` 够用。
库存里的 74273 / 74174 / HC595 都能替代 HC164，接法见接线表 §12。

### 5.3 为什么这个改法能成立

| 条件 | 14 µs 窗口内是否满足 |
|---|---|
| 地址稳定 | ✅ 由 74LS374 锁死，整个数据相不变 |
| 数据稳定 | ✅ 固件在 BusWrite 期间保持，字节间隔 20 µs ≫ 14 µs |
| `/CS` 低 | ✅ `Wn` 拉低，且 `LE=0` |
| `R/W` 低 | ✅ 同一个 `Wn` |
| 跨过 PHI2 上升沿 | ✅ 14 µs 必然覆盖 14 个上升沿 |
| 落在轮转第 1–6 周期 | ✅ 窗口 14 µs > 18−6 = 12 µs，无论相位如何都至少重叠一次 |
| 地址相不会误写 | ✅ 地址相 `A0=0` 时 `TRIG_n=1`，窗口根本不会打开 |

SID 寄存器是纯锁存器，窗口期间同一个值被采样 14 次，结果仍然是这个值。

**风险点**：`Wn` 宽度不能超过固件两次命令之间的间隔（Path A 一条 26.67 µs，
其中数据相到位到下次地址相 26 µs 左右）。14 µs 留了约 1.9 倍余量；
若 tap 取到第 18 级以上就会开始污染下一次写。

### 5.4 其他方向（不推荐）

1. **降 PHI2 频率**（例如 100 kHz）——**这条是错的，会变差**。
   命中率取决于"脉冲是否跨过上升沿"：脉冲宽 200 ns 固定不变时，
   周期从 1 µs 变成 10 µs，命中率反而从 20% 降到 2%。
   早先版本的本文档写过这个方向，是错的，已更正。

2. **用 `/WR` 当 PHI2** —— 不可行。SID 需要连续时钟驱动内部振荡器和包络，
   只在写的时候走时钟会让音符冻住。

3. **改 SPFM 固件把 `/WR` 拉宽到 14 µs** —— 效果与 §5.2 等价，
   但要动别人的固件，且会拖慢所有芯片的写速度、影响其它模块时序。
   板上一颗 74HC74 就够，没必要。

4. **换 FPGA 软核**（reDIP-SID / icesid）—— 能绕开问题，但那是重新做一块板子，
   已经不属于"把这个模块调通"的范畴。可作为备选记录：两者都需要 PHI2，
   其中 icesid 的 SPI 接口接收的是"地址+数据"两字节包，本质上和我们的两步写入同构。

## 6. 当前驱动默认值

```c
s_mode_w         = SID_WRITE_TWO_PHASE_NOP;  // 两步写入 + 硬件 NOP
s_phase_gap      = 3;                        // 3 个 0x80 tick
s_write_delay_us = 0;
s_write_repeat   = 12;
```

即每条寄存器写展开为：

```
[slot,0x80,addr] [0x80,0x80,0x80] [slot,0x81,data]     × 12
```

单条记录 9 字节 = 60 µs，12 条 = 720 µs。可稳定发声，但音高不跟随指令。
