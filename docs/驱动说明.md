# SID 6581 驱动说明

## 1. 文件

| 文件 | 作用 |
|---|---|
| `src/spfm_transport.c/h` | SPFM 字节流传输层（FTDI 打开、缓冲、flush、路径 A/B、dry-run 抓包） |

## 2. 一次寄存器写到底发生了什么

主机侧（驱动层）只发 4 字节：

```
[slot, 0x00, addr & 0x1F, data]
```

固件路径 A 展开成两次 BusWrite。当前硬件是
**74LS374 + 74HCT02 + 74HCT32 + 74HC74**（见 [接线表_374_02_min.md](接线表_374_02_min.md)）：

| 步 | 总线 | 74LS374 | 74HCT32/74HC74 | SID |
|---|---|---|---|---|
| 1 | A0=0, D=`addr&0x1F`, /WR 脉冲 | `LE = NOR(0,/WR 低) = 1`，`/WR` 下降沿捕获地址 | `TRIG_n = ¬A0∨/WR∨CSn = 1`，`Wn = 1` | **未选中**，忽略总线 |
| 2 | A0=1, D=`data`, /WR 脉冲 | `LE = 0`，保持上次地址 | `TRIG_n = 0` → 74HC74 出 `Wn = 0` | `/CS=0` 且 `R/W=0`（同一根线），写入 |

关键点：

- **地址相绝不会误写**：`A0=0` 使 `TRIG_n` 恒为 1，`Wn` 恒为 1，SID 根本不看总线。
  直接把 `CSn` 接到 SID 的 `/CS` 就会在地址相也写一次，写 `0x04` 时把 gate 清掉，
  表现为每次改频率都重启包络（咔哒声）。
- **`/CS` 和 `R/W` 必须是同一个信号 `Wn`**。旧接线把两者分成两路（`/CS` 过两个 NOR 门、
  `R/W` 裸接 `/WR`），SID 在同一个 PHI2 沿采样时会因为边沿错开而采到不一致的组合，
  这是"只有 repeat 才出声"的根因。
- **`TRIG_n` 必须先过 74HC74**。实测直接接 SID 会让单次写入明显失真；74HC74 把
  `TRIG_n` 重新打成满幅度陡边沿，并顺势多给约 30 ns 宽度。
- **`PHI2`（SID pin8）由独立 1 MHz 晶振供给**，与总线时序无关。

## 3. 三种写模式

`--write-mode` 选择，默认 `two-phase`（每寄存器一条 6 字节记录，1 次就够）。

### 3.0 为什么两相间隔基本不是问题

这一点值得先说清楚，因为它决定了要不要做时序退让。

SID 的写操作需要三件事同时/依次成立：地址稳定、`/CS` 有效、`/WR`（即 R/W）出现
低脉冲。在我们的方案里：

- **地址不是靠总线保持的，是靠 74LS374 保持的。** 地址相一结束，Q0–Q4 就锁死了，
  后面总线上的地址线随便变都不影响 SID。所以"两相之间隔多久"对地址稳定性没有意义。
- **地址相绝不会误写**：那段时间 `A0=0` 使 `TRIG_n=1`、`Wn=1`，SID 根本不看总线。
  这一点和两相间隔也无关。
- **数据相是一个完整的 `/WR` 低脉冲**：固件 `BusWrite` 拉低 `/WR`、写数据、再拉高，
  低电平宽度是几十到几百纳秒量级，而 SID 只需要 `/CS` 与 `/WR` 在 PHI2 的一个周期内
  建立即可（1 MHz 下 1 µs）。远够。

换句话说：**`two-phase`（以及 `path-a`）是安全的**，两相紧挨着发不会破坏任何东西。真正会被 USB 抖动
影响的是**不同寄存器之间**的间隔（0–125 µs），比如"写完频率到抬起 gate"之间，
而这个抖动对音符起音没有可感知影响。

下面两种模式是排查工具，不是必需品。

### 3.1 `path-a`

4 字节，一次命令，固件内部连续发两相。

```
[slot, 0x00, addr, data]
```

推荐模式，唯一不需要主机侧时序的模式。第 4 字节还在 UART 移位寄存器里时，
固件已经开始处理前 3 个字节了，所以两相之间是"固件解析耗时"，大概几微秒。

### 3.2 `phased`

两次路径 B，中间插 NOP：

```
[slot, 0x80, addr]  [0x80 × gap]  [slot, 0x81, data]
```

总线效果和 `path-a` 完全相同，但两相间隔由 `--gap N` 控制。用途是**排除法**：

- 如果 `phased --gap 0` 和 `path-a` 表现一致（应该一致，因为总线效果相同），
  说明固件路径 A 的实现没问题；
- 如果加大 gap 之后才响，问题在固件的两相实现细节上，跟接线无关；
- 如果无论 gap 多大都不响，问题在接线或供电，不在时序。

代价是每次写多一个 3 字节命令，吞吐降到路径 A 的 2/3。

### 3.3 `phased-flush`

字节流和 `phased` 相同，但两相之间强制 `FT_Write` 一次，插入一个 USB 往返
（几十 µs 到 1 ms）。极端诊断用：如果 `phased-flush` 能响而 `path-a` 不响，
时间尺度上的差异足以定位到微秒级以内的问题。

## 4. 初始化序列

`sid_init(slot, volume)` 做的事：

1. 25 个寄存器全写 0（`0x00`–`0x18`）。374 上电后 Q 输出不定，SID 也可能被总线
   杂波写进随机值，先全清。
2. `0x18 = volume`，音量。**复位后是 0，不写就完全没声音。**
3. 三个声部写中性参数：`AD=0x09`、`SR=0xF0`、`PW=0x800`（50%）、控制寄存器 0（gate 关）。
4. `0x15/0x16 = 0x7FF`、`0x17 = 0x00`：滤波器全开、无谐振、无通道路由，
   避免初始状态把声音滤没了。

总共 44 次寄存器写，`selftest` 会校验这个数字。

## 5. 声部 API

```c
sid_note_on(slot, voice, midi_note, wave, ad, sr);
```

写顺序固定为 `freq_lo → freq_hi → AD → SR → control(wave|GATE)`。gate 必须是最后
一次写，否则包络会在频率还没落定时启动，起音音高会飘。

```c
sid_note_off(slot, voice);   // control = wave，gate 清零，走 release
sid_note_kill(slot, voice);  // control = 0，立即静音
```

`note_off` 保留波形位，所以 release 段是同一个波形；`note_kill` 把波形也清掉，
输出直接回到 DC 0，不等包络。

## 6. 频率换算

```
freq_reg = round(f_out × 16777216 / PHI2)
```

1 MHz 下 `A4 = 7382`、`C4 = 4389`、`A2 = 1845`，和 `arduino_sid/midi.c` 一致。

`tools/gen_freq.py` 按公式生成 128 项表，同时和参考表比对。参考表 `freq[]` 有两处
问题（不影响常用音域，但值得知道）：

| MIDI | 音名 | 参考表 | 正确值 | 说明 |
|---|---|---|---|---|
| 23 | B0 | 581 | 518 | 抄成了 C#1 的值，八度错 |
| 99–107 | D#7–B7 | — | — | 整体低了一个半音（99 项写的是 D7 的值） |

常用音域（MIDI 12–98）逐项误差 ≤ 1%，直接用参考表也可以，但驱动用的是公式表。

## 7. 没有硬件时怎么验证

`selftest` 完全离线，检查 30 多项：

- 每条命令都是 4 字节、slot 3、`byte1 = 0x00`、寄存器 `< 0x20`；
- 寄存器掩码 `& 0x1F` 生效（0x38 变成 0x18）；
- `init` 产生 44 次写，且有一次 `0x18 = 0x0F`；
- `note_on` 是 5 次写且顺序正确、gate 在最后一次；
- 声部 2/3 的基址是 0x07/0x0E；
- `note_off` 清 gate 但保留波形，`note_kill` 全清；
- PWM 高字节只有 4 位、滤波器截止 11 位按 3+8 拆分；
- 频率表单调且 A4/C4/A2 三个锚点正确；
- `phased` 模式产生 `[addr] NOP×gap [data]`。

`--dry-run` 则把任何子命令的字节流解码成总线动作打印出来：

```
[   0] A slot3  BusWrite(A0=0,D=0x18)  BusWrite(A0=1,D=0x0F)   => SID reg 0x18 = 0x0F
```

## 8. 上机顺序建议

1. `sidtest list` 确认 FT232R 认到。
2. `sidtest checkup` —— 按提示量 1 MHz、+5 V、+12 V，然后看 pin 27 的直流变化，
   再放三角波。这一步能一次性分辨"没供电""/CS 没门控""A4 断线"三类问题。
3. `sidtest scale` —— 三个八度的音阶，听音高是否正确（音高偏差说明 PHI2 不是 1 MHz）。
4. `sidtest chord` —— 三个声部同时响，验证声部互不干扰。
5. `sidtest music` —— 三声部小曲，用来整体听感验证：
   - 声部 1：脉冲波旋律（`SID_CTL_PULSE`，PW 0x600）
   - 声部 2：三角波低音（`SID_CTL_TRI`）
   - 声部 3：噪声打击乐（`SID_CTL_NOISE`），底鼓 / 军鼓 / 踩镲

   内置三首：`twinkle`（小星星）、`ode`（欢乐颂）、`birthday`（生日快乐）。
   速度 `--bpm`（默认 120），重复 `--loops`，`--list` 列出全部。

   实现要点：SID 的包络只在 gate 的 **0→1 边沿**重启，所以连续同音必须先把
   gate 拉低再拉高，否则两个同音会连成一个长音。`mus_note_start()` 做的就是这件事。
   打击乐的"音高"其实是噪声时钟频率：`0x0500` 低 = 底鼓隆隆声，
   `0x0C00` 中 = 军鼓，`0x2000` 高 = 踩镲嘶声；配合极短的 AD/SR 让它几十毫秒内衰减完。
5. `sidtest noise` / `pwm` / `filter` —— 逐项验证噪声、PWM、滤波器。
6. 如果前几步有异常，用 `--write-mode phased --gap 8` 复测，对比是否为时序问题。

## 5. 音乐播放的包络设计

`sidtest music` 用三个声部同时演奏，包络是让它听起来像"演奏"而不是"风琴长音"的关键。

### 5.1 钢琴式包络：Sustain = 0

SID 的 ADSR 四个数字各 0..15：

```
AD = (attack << 4) | decay
SR = (sustain << 4) | release
```

**关键在 `sustain = 0`。** Sustain 是"按住键时保持的音量"：

- `sustain = 15` → 音符在 gate 期间一直满音量，直到下一个音符 → **无限延长，风琴感**
- `sustain = 0` → 音符衰减到 0 就自己消失，gate 只是让它在 release 段收尾 → **钢琴感**

当前的取值：

| 声部 | AD | SR | 含义 |
|---|---|---|---|
| 旋律（脉冲波） | `0x08` | `0x06` | A=0 瞬起，D=8（300 ms 衰减），S=0，R=6（204 ms 释放） |
| 低音（三角波） | `0x0A` | `0x06` | D=10（1500 ms），因为低音一小节才换一次 |
| 打击乐（噪声） | 见下 | S=0 | 衰减时间决定"鼓声"的长度 |

Decay 索引对应的实际时间见 `sid_adsr_decay_ms[]`：索引 7 = 240 ms、8 = 300 ms、
9 = 750 ms、10 = 1500 ms。

### 5.2 断音：提前一拍降 gate

`sustain = 0` 只保证音符自己会衰减，但相邻同音仍可能连起来。所以播放循环里会在
音符时值结束前**一个 tick** 主动降 gate：

```c
if (mleft == 1 && sc->melody[mi].ticks) sid_note_off(g_slot, 0);
```

这样每个音符都有一个明确的 0→1 边沿（重触发包络），断句清楚。

### 5.3 打击乐

SID 的噪声通道频率寄存器控制的是**噪声时钟速率**，不是音高：

| 鼓 | 频率寄存器 | Decay | 听感 |
|---|---|---|---|
| 底鼓 | `0x0400` | 8（300 ms） | 低频隆隆 |
| 军鼓 | `0x0E00` | 7（240 ms） | 中频短促 |
| 踩镲 | `0x2400` | 5（168 ms） | 高频嘶声 |

**衰减时间不能太短。** 早先版本用 0x00（6 ms）和 0x01（24 ms），听起来像数字干扰脉冲
而不是鼓声——24 ms 比人耳能识别的鼓声短太多。现在最短的踩镲也有 168 ms。

节奏型（以 1/16 音符为 tick，8 tick 一个循环）：`t%8==0` 底鼓，`t%8==4` 军鼓，
`t%4==2` 踩镲。

### 5.4 曲目来源

| 曲子 | 来源 |
|---|---|
| twinkle / ode / birthday | 手编，C 大调，旋律 + 和弦根音低音 |
| **bach** | 移植自 `arduino_sid/Source/SID_Bach/SID_Bach.ino`（Alexis Kotlowy, 2011, Public Domain），原始音高 OFFS=36，本实现整体 +12 抬高一个八度，避免与三角波低音撞在同一音区 |

Bach 原曲的 `notes[]` 数组共 40 项（含 3 个休止），移植时保持原音符顺序，
每音 2 个 tick，总长 82 tick。
