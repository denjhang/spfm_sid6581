# sidvgm 文件规范 v1.00

`.sidreg` 的升级格式。目标不是"能被 libvgm 播放"——libvgm 里根本没有 SID 设备
（`emu/SoundDevs.h` 的 `DEVID_*` 从 0x00 排到 0x29，没有 SID）——而是**把 VGM
的容器结构完整搬过来**：二进制头 + 相对偏移 + 等待命令 + 额外头 + GD3 标签 +
循环点，换掉 `.sidreg` 那种"一行一条、没有元数据、没法表达循环"的文本流。

参考实现读的是 libvgm 的播放器，不是 VGM 官方文档：

| 行为 | 出处 |
|---|---|
| 相对偏移（偏移相对自己所在字段，而非文件头） | `player/vgmplayer.cpp:126-131` `ReadRelOfs` |
| 头字段位置 0x04/0x14/0x1C/0x34/0xBC | `ParseHeader()` `vgmplayer.cpp:280-345` |
| 额外头：长度 + 时钟表 + 音量表 | `ParseXHdr_Data32/16()` `vgmplayer.cpp:377-424` |
| 时钟表项 = 1 字节类型 + 4 字节时钟 | 同上，步长 0x05 |
| GD3 = "Gd3 " + 版本 + EOT + 11 个 UTF-16LE 串 | `LoadTags()` `vgmplayer.cpp:437-476` |
| 0x61 等待 N 样本（3 字节），0x66 结束并跳循环 | `_CMD_INFO[]` `vgmplayer_cmdhandler.cpp:120` |
| 0x67 数据块 = `67 66 type len32 data` | `Cmd_DataBlock()` |
| 所有数值小端 | `ReadLE16/32` |

## 1. 文件总布局

```
+0x000  主头（0xC0 字节，实际用到 0xBB）
+0x0C0  额外头（extra header）
+...    芯片时钟表
+...    芯片音量表（本格式保留，写空表）
+data   命令流          ← 主头 0x34 处指向这里
+gd3    GD3 标签        ← 主头 0x14 处指向这里
+EOF    文件结束        ← 主头 0x04 处指向这里
```

偏移全部是**相对偏移**：存进文件的值 = 绝对位置 − 该字段自己的偏移。
例如数据从 0x0D8 开始，0x34 处写 `0x0D8 - 0x34 = 0x0A4`；值为 0 表示"不存在"。
这是 VGM 的原样规矩，不要改成绝对偏移。

## 2. 主头

所有多字节整数都是 **小端**。未列出的字节一律写 0。

| 偏移 | 类型 | 字段 | 本格式的含义 |
|---|---|---|---|
| +0x00 | 4B | magic | ASCII `"Svgm"`（`53 76 67 6D`）。注意 VGM 是 `"Vgm "`，我们故意区分。 |
| +0x04 | u32 | EOF 偏移 | 相对 0x04；= 文件长度 − 4 |
| +0x08 | u32 | 版本 | `0x00000100`（1.00）。高 16 位主版本，低 16 位次版本 |
| +0x0C | u32 | SN76489 时钟 | **0**。本格式不使用，留给结构对齐 |
| +0x10 | u32 | YM2413 时钟 | **0** |
| +0x14 | u32 | GD3 偏移 | 相对 0x14；0 = 无标签 |
| +0x18 | u32 | 总 tick 数 | 命令流里所有等待的累计（= 音乐总时长 × rate） |
| +0x1C | u32 | 循环偏移 | 相对 0x1C；0 = 不循环 |
| +0x20 | u32 | 循环段的 tick 数 | 从循环点起到结束的 tick 数 |
| +0x24 | u32 | rate | **SID 的 PHI2 频率**：PAL `985248`，NTSC `1022730` |
| +0x28 | u16 | SN76489 反馈 | 0 |
| +0x2A | u8 | SN76489 位宽 | 0 |
| +0x2B | u8 | SN76489 标志 | 0 |
| +0x2C | u32 | YM2612 时钟 | 0 |
| +0x30 | u32 | YM2151 时钟 | 0 |
| +0x34 | u32 | 数据偏移 | 相对 0x34 |
| +0x38–0x7B | — | 其余芯片时钟/标志 | 全 0（SID 不进固定头，走额外头） |
| +0x7C | u8 | 音量修正 | 0 = 不做 |
| +0x7D | u8 | 保留 | 0 |
| +0x7E | i8 | loop base | 0 = 播一遍后停在循环边界（见 §5） |
| +0x7F | u8 | loop modifier | 0 = 用 base 的决定，4.4 定点 |
| +0x80–0xBB | — | 后续芯片时钟等 | 全 0 |
| +0xBC | u32 | 额外头偏移 | 相对 0xBC |

**为什么 `rate` 是 PHI2 而不是 44100。** VGM 的 `rate` 定义就是"录音采样率"，
`0x61` 的等待数以它为单位。SID 的时间基准是 6502 周期，把 `rate` 定成 PHI2
之后，**一个等待数就是字面意义上的一个 CPU 周期**，写入时刻不需要任何换算也
不丢精度（44100 下每样本 22.7 µs，比一个周期粗 22 倍）。代价是不能直接喂给只
认 44100 的工具——但那些工具本来也放不了 SID。

## 3. 额外头

SID 芯片不在 VGM 的固定头里（固定头从 SN76489 排到 GA20，没有它），所以走 VGM
自己的扩展机制：

```
+0x00 u32  本块长度（含本字段），最小 0x0C
+0x04 u32  时钟表偏移（相对 0x04）
+0x08 u32  音量表偏移（相对 0x08）
```

**芯片时钟表**（libvgm `ParseXHdr_Data32`，步长 5 字节）：

```
+0  u8   芯片数 N
+1  N × { u8 类型; u32 时钟 }
```

SID 的类型码（占用 libvgm 未定义的空档，不与 0x00–0x29 冲突）：

| 类型码 | 含义 |
|---|---|
| 0x50 | MOS 6581 |
| 0x51 | MOS 8580 |
| 0x52 | SID，型号未知 |

`时钟` 字段写 PHI2 频率，与主头 `rate` 相同（冗余是 VGM 的既有约定：
多颗芯片时每颗单独给时钟）。

**芯片音量表**（libvgm `ParseXHdr_Data16`，步长 4 字节）：

```
+0  u8   芯片数 N
+1  N × { u8 类型; u8 标志(bit0=芯片号); u16 音量 }
```

本格式写 `N = 0`（SID 的 4 bit 音量是芯片自己的事，不做混音增益）。

## 4. 命令流

命令流从主头 `+0x34` 指向的位置开始，到 `0x66` 结束。每个命令的第一字节是操作码。
本格式只定义下列命令，**其余操作码禁止出现**（读器遇到即报错，不做"跳过 N 字节"
的猜测——VGM 那样做是因为它有几十种芯片，我们只有一种）。

| 操作码 | 总长 | 载荷 | 含义 |
|---|---|---|---|
| `0x69` | 3B | `reg u8, val u8` | 写 **SID #0**（`$D400`）的寄存器 |
| `0x6A` | 3B | `reg u8, val u8` | 写 **SID #1** |
| `0x6B` | 3B | `reg u8, val u8` | 写 **SID #2** |
| `0x61` | 3B | `n u16` | 前进 n 个 tick（n ≥ 1；n = 0 非法） |
| `0x66` | 1B | — | 命令流结束 |
| `0x67` | 7B+ | `0x66, type u8, len u32, data` | 数据块（保留给 PCM/digi 采样，见 §6） |
| `0x90`–`0x95` | 见 VGM | — | DAC 流控制，**原样沿用 VGM 语义**（见 §6） |

`reg` 是 SID 寄存器号 `0x00`–`0x1F`（不是 `$D400` 起的绝对地址）；`sid` 索引
对应额外头里的第几颗芯片，所以 `0x6A` 必须只在额外头声明了第 2 颗时出现。

**写命令不推进时间。** 同一 tick 上的多条写入按文件顺序发出，不给中间插等待——
这正是 `.sidreg` 里多条同 `t_ms` 行的含义，也是真机上 `play()` 在一帧内连写几十
个寄存器的顺序。

`0x61` 分两字节小端，最大 65535 tick。要跨更长间隔（一整帧 PAL 是 19656 tick，
安全；但 CIA 驱动的曲子可能有更长静默）就连续写多条 `0x61`，读器把它们累加。

VGM 的 `0x62`（等 735 样本）/`0x63`（等 882 样本）/`0x70`–`0x7F`（等 1–16 样本）
这里**不使用**：它们的数值是按 44100 定的，在 PHI2 时间基上没有意义。一帧就用
`0x61 19656`（PAL）/ `0x61 17095`（NTSC）显式写出——反正一帧的写入本来就是一批。

## 5. 循环语义

`0x66` 在 VGM 里就是"结束并跳回 `loop_offset`"，跳转时累加循环计数并按
`loop base/modifier` 决定播几遍。本格式原样继承：

- `+0x1C = 0`：播一遍就停。**当前写器永远写 0**——一个 `.sid` 里没有循环点
  （见《寄存器抽取与SID模型审计》§7.3），所以没有东西可以填。
- `+0x1C ≠ 0`：播到 `0x66` 时把时间轴跳回该位置，重复 `loop base` 指定的次数。
  这是**给人工标注留的能力**：想循环某段，把那个 tick 的命令偏移写进 0x1C 即可，
  不需要改播放器。

读器必须校验：`loop_offset` 落在命令流范围内、`loop_ticks ≤ total_ticks`，
否则按"不循环"处理（与 libvgm `ParseHeader()` 的容错一致）。

## 6. 预留：PCM / digi

RSID 的 digi 采样不需要单独的机制——它就是密集的 `$D418` 写入，走 `0x69`。
只有在把采样搬成"预存波形 + 定时推流"时才需要下面两个，本版写器不产出：

- **`0x67` 数据块**：`type` 高 2 位是压缩标志（`0x00` 未压缩），低 6 位是块号。
  PC 上的 `.sidreg` 没有这个概念，所以块号从 0 起自由分配。
- **`0x90`–`0x95` DAC 流控制**：`Setup`/`SetData`/`SetFrequency`/`PlayData_Loc`/
  `Stop` 的字节布局与 VGM 完全一致（`vgmplayer_cmdhandler.cpp`
  `Cmd_DACCtrl_*`），`setup` 里的 `chipCmd` 指到本格式的 `0x6A`/`0x6B` 即可把
  采样流推到第二颗芯片的音量寄存器。

## 7. GD3 标签

结构照抄 VGM：

```
+0x00  4B   "Gd3 "
+0x04  u32  版本 0x00000100
+0x08  u32  EOT 偏移（相对 0x0C，即字符串块长度）
+0x0C  ...  11 个 UTF-16LE 字符串，每个以 0x0000 结尾
```

顺序固定，缺的写空串：

| # | 字段 | sidvgm 用法 |
|---|---|---|
| 1 | TITLE | `name`（32 字节里的，必要时截断） |
| 2 | TITLE-JPN | 空 |
| 3 | GAME | 空 |
| 4 | GAME-JPN | 空 |
| 5 | SYSTEM | 空 |
| 6 | SYSTEM-JPN | 空 |
| 7 | ARTIST | `author` |
| 8 | ARTIST-JPN | 空 |
| 9 | DATE | `released` |
| 10 | ENCODED_BY | `"sidvgm 1.00"` |
| 11 | COMMENT | 一行结构化说明，见下 |

COMMENT 的固定格式（分号分隔，读器按关键字取，不认识的键忽略）：

```
format=PSID; clock=PAL; sid0=6581; sid1=8580; subsong=1/23; play_hz=50.125; source=Golden_Axe.sid
```

## 8. 完整示例

`sid/Golden_Axe.sid` 前 3 条写入（子曲 1，共 3 条同 tick），外加一个 19655 tick
的帧间隔、再来一条：

```
00000000  53 76 67 6D  ...   "Svgm"
+0x04  EOF-4
+0x08  00 01 00 00          版本 1.00
+0x0C  00 00 00 00          SN76489 时钟 = 0
+0x10  00 00 00 00          YM2413 时钟 = 0
+0x14  GD3-0x14
+0x18  39 4D 00 00          19655+19655 = 39310 tick
+0x1C  00 00 00 00          不循环
+0x20  00 00 00 00
+0x24  C0 0B 0F 00          985248 = 0x000F0BC0
+0x34  data-0x34
+0x7E  00                 loop base 0
+0x7F  00                 loop modifier 0
+0xBC  extra-0xBC

extra (+0x0C0):
+0x00  0C 00 00 00          块长 12
+0x04  08 00 00 00          时钟表在 0xC4+8 = 0xCC
+0x08  0A 00 00 00          音量表在 0xC8+0x0A = 0xD2

时钟表 (+0xCC):
+0x00  01                   1 颗
+0x01  50 C0 0B 0F 00       类型 0x50(6581)，时钟 985248

音量表 (+0xD2):
+0x00  00                   0 颗

数据 (+0xD3，主头 0x34 处写 0xD3−0x34 = 0x9F):
  69 18 1F        写 #0 的 0x18 = 0x1F
  69 14 00        写 #0 的 0x14 = 0x00
  69 13 00        写 #0 的 0x13 = 0x00
  61 27 4C        等 19655 tick (0x4CC7)
  69 04 21        写 #0 的 0x04 = 0x21
  66              结束

GD3 (紧接数据之后):
  47 64 33 20     "Gd3 "
  00 01 00 00     版本 1.00
  ...             EOT
  47 00 6F 00 ... "Golden Axe" 的 UTF-16LE
```

`+0x04` 的值 = 文件长度 − 4，`+0xBC` 的值 = 0xC0 − 0xBC = 0x04。

## 9. 与 `.sidreg` 的对照

| 能力 | `.sidreg` | `.sidvgm` |
|---|---|---|
| 时间基 | 浮点毫秒，`%.4f` | 整数 tick（= CPU 周期），无损 |
| 芯片归属 | 第 4 字段，缺省 = 0 | 操作码本身（0x69/6A/6B） |
| 元数据 | 无 | GD3（标题/作者/年份/格式/型号/子曲） |
| 循环点 | 无 | 主头 0x1C/0x20 |
| 采样率/时钟 | 无 | 主头 0x24 + 额外头时钟表 |
| 扩展 | 加字段就破坏老读器 | 数据块 + DAC 流，VGM 原样 |
| 可读性 | 纯文本，能手改 | 二进制，配 `sidvgm-dump` |
| 体积 | 38 KB / 2330 条 | 约 9 KB（3 字节/条 + 3 字节/间隔） |

`.sidreg` 保留：它是 STC32G 工具链的交换格式，且已有一批缓存落在磁盘上。
读器两条路都认，写器按扩展名决定。

## 10. 读器必须做的校验

参考 libvgm `ParseHeader()` 的容错清单，按 SID 的实际情况裁剪：

1. magic 不等于 `"Svgm"` → 拒绝（不猜是不是 `.sidreg`）。
2. `eof_ofs + 4` 大于文件长度 → 用真实文件长度（libvgm 同款处理）。
3. `data_ofs` 小于 0xC0 或超出文件 → 拒绝。
4. `gd3_ofs` 不在 `[data_ofs, eof)` → 忽略标签，不报错。
5. 额外头块长 < 0x08 → 跳过整个额外头；时钟表项越界 → 截断。
6. `ram_rate = 0` → 拒绝（无法把 tick 换算成毫秒）。
7. `0x61` 的 n = 0 → 忽略该命令（防止死循环，libvgm 的 `Ignored Zero-Sample-Loop` 同理）。
8. 命令流读到 `eof` 仍没遇到 `0x66` → 当正常结束（有些写器省掉结束符）。
9. `loop_ofs` 不在命令流范围内，或 `loop_ticks` 为 0 → 当不循环（libvgm 同样两条都查）。
