# sidvgm 文件规范 v1.00

`.sidreg` 的升级格式。目标是**把 VGM 的容器结构完整搬过来**：二进制头 + 相对
偏移 + 等待命令 + 额外头 + GD3 标签 + 循环点，换掉 `.sidreg` 那种"一行一条、
没有元数据、没法表达循环"的文本流。

做法是复用 VGM 生态的结构，不是自创格式：字节布局、偏移规则、命令语义、GD3
全部按 VGM 的定义来。**不追求现有 vgmplay 直接播放**——SID 芯片类型是新的，
由专门的分支播放器和分支工具解析；要保证的只是"结构和语义与 VGM 一致"。

参考实现读的是 libvgm 的播放器，不是 VGM 官方文档：

| 行为 | 出处 |
|---|---|
| 相对偏移（偏移相对自己所在字段，而非文件头） | `player/vgmplayer.cpp:126-131` `ReadRelOfs` |
| 头字段位置 0x04/0x14/0x1C/0x24/0x34/0xBC | `ParseHeader()` `vgmplayer.cpp:280-345` |
| **tick 基准恒为 44100** | `RefreshTSRates()` `vgmplayer.cpp:769`：`_tsDiv = 44100` |
| `0x24` 是地区标记（50/60/0），不是采样率 | `VGM_HEADER.recordHz` 注释 `vgmplayer.hpp:36` |
| 额外头：长度 + 时钟表 + 音量表 | `ParseXHdr_Data32/16()` `vgmplayer.cpp:377-424` |
| 时钟表项 = 1 字节类型 + 4 字节时钟，步长 0x05 | 同上 |
| 按类型查时钟（不是按序号） | `GetChipClock()` `vgmplayer.cpp:1048` |
| GD3 = "Gd3 " + 版本 + EOT + 11 个 UTF-16LE 串 | `LoadTags()` `vgmplayer.cpp:437-476` |
| 0x61 等待 N tick（3 字节），0x66 结束并跳循环 | `_CMD_INFO[]` `vgmplayer_cmdhandler.cpp:120` |
| 未知命令按其声明长度**跳过**而不是中止 | `Cmd_unknown()`（与 `Cmd_invalid` 相对） |
| 所有数值小端 | `ReadLE16/32` |

## 1. 文件总布局

```
+0x000  主头（0xC0 字节，实际用到 0xBB）
+0x0C0  额外头（extra header，12 字节）
+0x0CC  芯片时钟表
+...    芯片音量表（本格式写空表）
+data   命令流          ← 主头 0x34 处指向这里
+gd3    GD3 标签        ← 主头 0x14 处指向这里
+EOF    文件结束        ← 主头 0x04 处指向这里
```

偏移全部是**相对偏移**：存进文件的值 = 绝对位置 − 该字段自己的偏移。
例如数据从 0x0D3 开始，0x34 处写 `0x0D3 - 0x34 = 0x9F`；值为 0 表示"不存在"。
这是 VGM 的原样规矩，不要改成绝对偏移。

## 2. 主头

所有多字节整数都是 **小端**。未列出的字节一律写 0。

| 偏移 | 类型 | 字段 | 本格式的含义 |
|---|---|---|---|
| +0x00 | 4B | magic | ASCII `"Svgm"`（`53 76 67 6D`）。VGM 是 `"Vgm "`，故意区分 |
| +0x04 | u32 | EOF 偏移 | 相对 0x04；= 文件长度 − 4 |
| +0x08 | u32 | 版本 | `0x00000100`（1.00） |
| +0x0C | u32 | SN76489 时钟 | 0（结构占位） |
| +0x10 | u32 | YM2413 时钟 | 0 |
| +0x14 | u32 | GD3 偏移 | 相对 0x14；0 = 无标签 |
| +0x18 | u32 | 总 tick 数 | 命令流里所有等待的累计（1 tick = 1/44100 s） |
| +0x1C | u32 | 循环偏移 | 相对 0x1C；0 = 不循环（当前写器恒 0，见 §5） |
| +0x20 | u32 | 循环段 tick 数 | 从循环点起到结束的 tick 数 |
| +0x24 | u32 | **地区标记** | PAL 写 50，NTSC 写 60，0 = 不做速度换算。**不是采样率** |
| +0x28 | u16 | SN76489 反馈 | 0 |
| +0x2A | u8 | SN76489 位宽 | 0 |
| +0x2B | u8 | SN76489 标志 | 0 |
| +0x2C | u32 | YM2612 时钟 | 0 |
| +0x30 | u32 | YM2151 时钟 | 0 |
| +0x34 | u32 | 数据偏移 | 相对 0x34 |
| +0x38–0x7B | — | 其余芯片时钟/标志 | 全 0（SID 走额外头） |
| +0x7C | u8 | 音量修正 | 0 |
| +0x7D | u8 | 保留 | 0 |
| +0x7E | i8 | loop base | 0 = 播一遍后停在循环边界 |
| +0x7F | u8 | loop modifier | 0 = 用 base 的决定，4.4 定点 |
| +0x80–0xBB | — | 后续芯片时钟等 | 全 0 |
| +0xBC | u32 | 额外头偏移 | 相对 0xBC |

**时间基。** tick 恒为 1/44100 秒，与 VGM 完全一致（libvgm 的
`RefreshTSRates()` 把 `_tsDiv` 写死 44100）。SID 的 PHI2 时钟只用于两处：
额外头的芯片时钟表，和事件时间戳到 tick 的换算。写器用绝对时间戳直接换算
（`tick = t_ms × 44.1`），不做逐帧累加，所以回读不会有累积漂移；实测 2330
条事件的往返最大误差 0.011 ms（半个 tick）。

`0x24` 写地区标记而不是时钟频率，是因为 libvgm 只在"用户指定了 playbackHz
且文件有 recordHz"时才拿它做倍速修正；把它填成 985248 会让
`_ttMult *= 985248`，播放速度直接快 22 倍。

## 3. 额外头

SID 不在 VGM 的固定头里（固定头从 SN76489 排到 GA20），所以走 VGM 自己的扩展
机制：

```
+0x00 u32  本块长度（含本字段），12
+0x04 u32  时钟表偏移（相对 0x04）
+0x08 u32  音量表偏移（相对 0x08）
```

**芯片时钟表**（libvgm `ParseXHdr_Data32`，步长 5 字节）：

```
+0  u8   芯片数 N（= 本文件实际使用的 SID 颗数，1..3）
+1  N × { u8 芯片类型; u32 时钟 }
```

**三颗 SID 各占一个独立的芯片类型号**，这样按类型查时钟永远不歧义
（libvgm 的 `GetChipClock()` 就是按类型线性查表）：

| 类型码 | 含义 |
|---|---|
| 0x65 | SID #0（`$D400`） |
| 0x66 | SID #1（`$D420` 等） |
| 0x67 | SID #2（`$D440` 等） |

0x65–0x67 落在 libvgm `DEVID_*` 空间（0x00–0x29）之外，不与任何既有设备冲突。
时钟写 PHI2 频率（PAL 985248 / NTSC 1022730），与 SID 实际运行频率一致。

**芯片音量表**（libvgm `ParseXHdr_Data16`，步长 4 字节）：

```
+0  u8   芯片数 N
+1  N × { u8 类型; u8 标志(bit0=芯片号); u16 音量 }
```

本格式写 `N = 0`（SID 的 4 bit 音量就是 DAC，不做混音增益）。

## 4. 命令流

命令流从主头 `+0x34` 指向的位置开始，到 `0x66` 结束。

| 操作码 | 总长 | 载荷 | 含义 |
|---|---|---|---|
| `0x41` | 3B | `reg u8, val u8` | 写 SID #0 的寄存器 |
| `0x42` | 3B | `reg u8, val u8` | 写 SID #1 |
| `0x43` | 3B | `reg u8, val u8` | 写 SID #2 |
| `0x61` | 3B | `n u16` | 前进 n tick（n ≥ 1；n = 0 非法） |
| `0x66` | 1B | — | 命令流结束 |
| `0x67` | 7B+ | `0x66, type u8, len u32, data` | 数据块（预留给 PCM，见 §6） |
| `0x90`–`0x95` | 见 VGM | — | DAC 流控制，沿用 VGM 语义（见 §6） |

三个写命令选 `0x41/0x42/0x43` 的原因：VGM 的命令表里 `0x41`–`0x4E` 是
"unknown, length 3"——**长度恰好是 opcode+reg+data**，和 SID 写入同形。标准
libvgm 播放器遇到它们会按声明长度跳过（`Cmd_unknown`），不会中止，也不会把
后面的字节读歪。这是"结构对齐"能做到的最好结果：不认识的播放器安静跳过，
认识的分支播放器按 SID 写处理。

`reg` 是 SID 寄存器号 `0x00`–`0x1F`（不是 `$D400` 起的绝对地址）。`sid` 索引
对应额外头时钟表里的第几颗芯片，所以 `0x42`/`0x43` 只在声明了第 2/3 颗时出现。

**写命令不推进时间。** 同一 tick 上的多条写入按文件顺序发出，不给中间插等待——
这正是 `.sidreg` 里多条同 `t_ms` 行的含义，也是真机上 `play()` 在一帧内连写
几十个寄存器的顺序。

`0x61` 最大 65535 tick（≈1.49 s）。更长的静默就连续写多条 `0x61`，读器累加。
VGM 的 `0x62`/`0x63`（等 735/882 样本）与 `0x70`–`0x7F`（等 1–16 样本）本格式
**不使用**：它们只是 44100 基准上的简写，`0x61` 全都能表达，少一套编码。

## 5. 循环语义

`0x66` 在 VGM 里就是"结束并跳回 `loop_offset`"，跳转时累加循环计数并按
`loop base`/`modifier` 决定播几遍。本格式原样继承：

- `+0x1C = 0`：播一遍就停。**当前写器永远写 0**——一个 `.sid` 里没有循环点，
  所以录制阶段没有东西可填。
- `+0x1C ≠ 0`：播到 `0x66` 时把时间轴跳回该位置。

**循环点是录制完成之后、由另外的工具标注的**（分析工具、人工标注、或播放器
探测），不属于录制器的职责。本格式只负责让这个字段有正确的结构位置和语义。
读器必须校验：`loop_offset` 落在命令流范围内、`loop_ticks ≤ total_ticks`，
否则按"不循环"处理（与 libvgm `ParseHeader()` 的容错一致）。

## 6. 预留：PCM / digi

RSID 的 digi 采样不需要单独机制——它就是密集的 `$D418` 写入，走 `0x41`。
只有把采样搬成"预存波形 + 定时推流"时才需要下面两个，本版写器不产出：

- **`0x67` 数据块**：`type` 高 2 位是压缩标志（`0x00` 未压缩），低 6 位是块号。
- **`0x90`–`0x95` DAC 流控制**：字节布局与 VGM 完全一致（`vgmplayer_cmdhandler.cpp`
  的 `Cmd_DACCtrl_*`），`setup` 里的 `chipCmd` 指到 `0x42`/`0x43` 即可把采样流
  推到第二颗芯片的音量寄存器。

## 7. GD3 标签

结构照抄 VGM：

```
+0x00  4B   "Gd3 "
+0x04  u32  版本 0x00000100
+0x08  u32  EOT 偏移（相对 0x0C，即字符串块长度）
+0x0C  ...  11 个 UTF-16LE 字符串，每个以 0x0000 结尾
```

顺序固定，缺的写空串：

| # | 字段 | sidvgm 用法 |
|---|---|---|
| 1 | TITLE | `name` |
| 2 | TITLE-JPN | 空 |
| 3 | GAME | 空 |
| 4 | GAME-JPN | 空 |
| 5 | SYSTEM | 空 |
| 6 | SYSTEM-JPN | 空 |
| 7 | ARTIST | `author` |
| 8 | ARTIST-JPN | 空 |
| 9 | DATE | `released`（header +86） |
| 10 | ENCODED_BY | `"sidvgm 1.00"` |
| 11 | COMMENT | 结构化一行，见下 |

COMMENT 固定格式（分号分隔，读器按关键字取，不认识的键忽略）：

```
format=PSID; clock=PAL; subsong=1/23; play_hz=50.125; source=Golden_Axe.sid
```

## 8. 完整示例

`sid/Golden_Axe.sid` 子曲 1、2 秒，前 3 条同 tick 写入、一个帧间隔、再来一条：

```
主头:
+0x00  53 76 67 6D           "Svgm"
+0x04  EOF-4
+0x08  00 01 00 00           版本 1.00
+0x14  GD3-0x14
+0x18  71 54 01 00           87100 tick ≈ 1.975 s
+0x1C  00 00 00 00           不循环
+0x20  00 00 00 00
+0x24  32 00 00 00           50 = PAL
+0x34  9F 00 00 00           数据在 0xD3（0xD3-0x34）
+0x7E  00                    loop base
+0x7F  00                    loop modifier
+0xBC  04 00 00 00           额外头在 0xC0（0xC0-0xBC）

额外头 (+0xC0):
+0x00  0C 00 00 00          块长 12
+0x04  08 00 00 00          时钟表 = 0xC4+8 = 0xCC
+0x08  0A 00 00 00          音量表 = 0xC8+0x0A = 0xD2

时钟表 (+0xCC):
+0x00  01                   1 颗
+0x01  65 C0 0B 0F 00       类型 0x65 (SID0)，时钟 985248

音量表 (+0xD2):
+0x00  00                   0 颗

数据 (+0xD3):
  41 18 1F        写 SID0 的 0x18 = 0x1F
  41 14 00        写 SID0 的 0x14 = 0x00
  41 13 00        写 SID0 的 0x13 = 0x00
  61 70 03        等 880 tick（19655 周期 / 985248 Hz × 44100）
  41 04 21        写 SID0 的 0x04 = 0x21
  66              结束
```

## 9. 与 `.sidreg` 的对照

| 能力 | `.sidreg` | `.sidvgm` |
|---|---|---|
| 时间基 | 浮点毫秒 | 整数 tick（1/44100 s） |
| 芯片归属 | 第 4 字段，缺省 = 0 | 操作码本身（0x41/0x42/0x43） |
| 元数据 | 无 | GD3（标题/作者/年份/格式/子曲） |
| 循环点 | 无 | 主头 0x1C/0x20（结构就位，录制裁不填） |
| 时钟/地区 | 无 | 额外头时钟表 + 主头 0x24 |
| 扩展 | 加字段就破坏老读器 | 数据块 + DAC 流，VGM 原样 |
| 可读性 | 纯文本 | 二进制，配 `--dump` |
| 体积 | 2330 条 = 38 KB | 同一条数 = 8.4 KB |

`.sidreg` 保留：STC32G 工具链的交换格式，磁盘上已有一批缓存。

## 10. 读器必须做的校验

参考 libvgm `ParseHeader()` 的容错清单：

1. magic ≠ `"Svgm"` → 拒绝。
2. `eof_ofs + 4` 大于文件长度 → 用真实文件长度。
3. `data_ofs` 小于 0xC0 或超出文件 → 拒绝。
4. `gd3_ofs` 不在 `[data_ofs, eof)` → 忽略标签，不报错。
5. 额外头块长 < 8 → 跳过整个额外头；时钟表项越界 → 截断。
6. `0x61` 的 n = 0 → 忽略该命令（防死循环）。
7. 命令流读到 `eof` 仍没遇到 `0x66` → 当正常结束。
8. `loop_ofs` 不在命令流内，或 `loop_ticks` 为 0 → 当不循环。
9. 芯片类型不在 0x65–0x67 → 该时钟表项跳过（不认识就当没有这颗）。
